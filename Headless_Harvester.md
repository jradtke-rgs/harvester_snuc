There are a handful of relevant GitHub issues in the harvester/harvester repo, all pointing at the same underlying limitation: the installer TUI is hardcoded to the first detected console/VGA tty unless you explicitly redirect it. Here's what's out there:

1. [BUG] The installer and dashboard are always displayed on tty1 — Issue #485 The original report of this behavior. The harvester-installer and the Dashboard after installation are always tied to tty1, which prevents users from seeing the installer or the dashboard on headless servers or cloud instances that only come with a serial console. Reported against KVM VMs and Equinix Metal bare metal, tested with virsh console. The expected fix noted was that users should be able to use the installer and dashboard on serial console.

2. [Question] Can you provide instructions to install harvester without VGA (headless) — Issue #3393 A user who could reach the ttyS0 login prompt ("Welcome to SUSE Linux Enterprise Micro for Rancher 5.2 (x86_64)... ens4: rancher login:") but couldn't figure out how to drive the interactive installer TUI options from there. This is essentially the same problem you're facing on the SNUC/EE-8700 if NANO-BMC turns out to be SOL-only.

3. [DOC] Tips to install Harvester with a serial console — Issue #5637 This is the most actionable one — it's a doc request that includes the actual workaround, which is what I based the earlier GRUB-edit steps on: at the GRUB screen, edit the VGA 1024x768 entry and add console=ttyS4,115200 (adjust tty number to your hardware), since serial output alone often won't let you boot straight into a working tty. Maximize the terminal running minicom, log in with rancher:rancher, sudo su -, then run setterm --resize, followed by start-installer.sh to launch the installer. It's tagged require/doc — meaning as of that issue, this workaround still isn't in the official docs, it only lives in the GitHub issue thread.

Bottom line: there's no built-in "headless mode" flag for the ISO-based interactive installer — the community workaround is the manual GRUB console=ttyS<N> edit + setterm --resize + start-installer.sh dance from #5637, and it's not officially documented. That's exactly why I'd steer you toward the PXE + config.yaml or iPXE automatic install path for the actual customer engagement (per install.tty in the config, or harvester.install.tty= kernel arg) — those bypass the interactive TUI entirely and don't depend on this still-open documentation gap.
